## 数据合同与参数复用

源EEG数据沿用BNCI2014_001、Cho2017、Lee2019_MI、PhysionetMI。目标开发体系使用Stieger2021既有参与者划分：40元训练、11元验证、11内部留出为登记分组，实际有效名单与会话数以冻结manifest和结果为准。

预处理保持11个clinic通道、CAR后的10维有效空间、128Hz、8–30Hz、固定窗/滤波/归一化合同。原始前20个获取位置构成校准预算，QC失败不补采；后续真实完整run作未来查询。第二至六轮的小预算比较始终在相同B20未来查询上评价。

冻结的源EEGNet、源参考协方差和原数据缓存可以共用。新低维字典的数值配方不同，不能因为名字相似就复用为已完成训练；只有身份、输入、配方和完整产物匹配才复用。不同轮次的输出与状态目录独立。

## 历史故障与已落实的工程改动

| 历史现象 | 已落实处理 | 记录解释 |
|---|---|---|
| 原阶段每次重跑全量test/pilot/全树SHA | 直接训练入口与后续轮复用已完成工程产物，不把全量检查放学校启动链 | 实际需要的输入读取仍会产生I/O |
| pilot已200更新但结果清单失败 | 保留四份checkpoint，单独完成清单环节 | 不能因外层失败就重算200次更新 |
| 总日志只有控制器心跳、真实异常藏在子日志 | shell启动标记、无缓冲输出、任务error/traceback、outer/session计数与三槽进度 | 心跳或SlurmRUNNING本身不是优化计数 |
| 66数组元素触发QOSMaxSubmitJobPerUserLimit | R2/R3滚动少量独立单GPU作业；R4/R5单三卡allocation | `%2/%3`限制并行数，不减少已提交数组元素数 |
| AssocGrpGRES | 保留队列原因、等待关联GPU配额 | 是资源等待，不靠重跑pytest解决 |
| 共享文件系统慢/旧glibc/Bash4.2/离线环境 | 已有运行缓存与兼容安装、固定依赖和信号处理；各轮软件验证覆盖相关路径 | CPU验证不等于所有真实GPU节点现场验证 |
| 单任务异常导致全轮取消 | 后续worker记录错误，其他独立任务继续 | 失败依赖项仍需修复，不能把等待项冒充完成 |
| GitHub网络失败影响训练 | 独立监控与重试；本地先写模型/预测 | 上传状态不代表checkpoint已完整备份 |

工程修复不改变前缀预算、既有数据划分、正式1000步元训练预算或主比较定义。原累计43200秒为历史约束，直接恢复版及后续各轮取消累计12小时上限。

## 断点、续交和完成的定义

后续轮字典训练每10次outer更新保存双代checkpoint、优化器/门与随机状态；评价逐会话原子保存，完整任务由`result.json.status=COMPLETE`判断。1000步训练已结束但还在验证、选模、留出预测或诊断时，尚不是整项完成。

同身份完成产物复用，未完成项读取最近有效断点；最近保存以后的少量工作可能重复。改变算法或科学配方使用新目录，日志/调度修复可继续兼容的旧结果。不能仅凭跨节点迁移或存在checkpoint就宣称每次恢复逐位等价。

无累计12小时上限不代表集群没有单次作业时限。R2/R3默认单次5天3小时并USR1提前保存；R2的requeue受站点权限约束，R3由控制器对账后续交，R4/R5也按单作业续交。明确主动取消应保持停止。存储/数值错误需修复，不采用无限重试掩盖失败。

## 进度和回传读法

| 观测 | 能说明什么 |
|---|---|
| PACKAGE_READY/PREPARED | 包和计划准备完毕 |
| DETACHED_PROCESSES_STARTED | login后台控制器/监控进程已启动 |
| job_id或提交回执 | 调度提交已有记录 |
| PENDING/QUEUED/队列原因 | 等待资源/配额 |
| TRAIN_PROCESS_STARTED | 节点批脚本已执行 |
| outer_update、会话数、完成项增长 | 对应实际计算有推进 |
| PARTIAL | 部分结果可读，主比较未必齐备 |
| COMPLETE和全部所需配对结果 | 才可按预定统计方案解释整组完成 |

第二至六轮每180秒尝试GitHub同步到各自分支，失败独立重试；status中的updated_utc表示源快照生成时间，GitHub提交时间表示该版本回传时间；均不证明所有作业仍在运行。完整checkpoint、逐会话概率、日志和报告CSV保存在学校共享目录。
