# 第一轮冻结文件散列复用修复（2026-10-26）

第一轮截图显示一个筛选行动总计约 1699 秒，原生计算阶段约 162 秒；大量时间消耗在多个验证入口反复读取冻结文件进行 SHA256 校验。另一个子进程的堆栈位于窗口接受和源缓存接受检查，`verify_meta_inputs` 单次耗时 885.601 秒。每五分钟出现的 `Timeout` 是原操作层的 faulthandler 定时堆栈，并没有终止进程。

本修复继续执行原验证器和真实 GPU 探测，只复用原散列函数实际计算过的文件 SHA256。缓存按解析路径、设备、inode、大小、纳秒 mtime/ctime 识别文件，命中时再次检查文件身份；原始文件变化则重新计算。实现版本和源散列函数代码的 SHA256 也属于缓存命名空间，不用调用者声明的期望 SHA 伪造缓存。原验证器仍比较缓存返回的实际散列与冻结凭据。

共享缓存位于 `runs/training_campaign_parallel_v1/digest-cache-v1/index.json`，采用锁和普通原子替换合并三张卡的真实散列记录。缓存损坏、目录不可写或锁忙会回到原路径，不增加新的训练前阻断。非训练数据、模型或协议文件不复制；无全数据扫描、无额外下载、无登录节点 Torch 导入。

`FIX-PAPER3-R1-STARTUP-CACHE.py` 只更新已声明第一轮包的 `action_startup.py`，以及当前包和原 direct 包的 `r1_spawn_bootstrap.py` 操作入口。原 GPU 迁移策略、spawn 修复、F0 身份修复保持。新的主线行动和独立子阶段均加载缓存，现有子进程不发送信号、不取消、不重新排队。

第一次遇到未缓存文件仍需原生读取；后续验证阶段和新任务可以命中。原逐试次 QC 和尚未见过的数据仍需正常检查，不能承诺每个启动立即完成。日志会出现 `R1_FILE_DIGEST_CACHE_ACTIVE`，每隔一段时间更新 `R1_FILE_DIGEST_CACHE_PROGRESS`，结束打印 `R1_FILE_DIGEST_CACHE_SUMMARY` 的命中数与复用字节。

安装成功标志为 `R1_STARTUP_CACHE_REPAIR_APPLIED`；它表示后续入口已切换，不表示当前子进程立即变快或整个第一轮已经完成。原断点、结果、任务键、计划和训练调度保持。

第一轮原有进度推送和按轮次的结果回传继续运行，本修复不替换上传器，也不将任务监控快照称为完整论文结果包。

验证见 `AUDIT_R1_DIGEST_CACHE.json`、`VALIDATION.json` 和测试源码；测试包含跨进程复用、输入变化、符号链接变化、并发合并、缓存故障回退，以及 GPU 探测和原验证器在暖缓存时仍执行。当前没有直接连接学校服务器，实际采用情况需看后续新行动日志。
