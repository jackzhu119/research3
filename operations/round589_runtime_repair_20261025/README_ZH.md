# 第五、八轮修复及第九轮预防修复

学校实际日志确认，第五轮拆分运行缺少 cuBLAS 确定性配置，第八轮 CUDA 计算损失时 Float/Double 索引赋值类型不匹配。扩展审查另确认第五轮 EA 对照误分派，以及第九轮继承了相同损失类型错误。

本修复覆盖：

1. 第五轮：在导入 Torch 前设置合法的 `CUBLAS_WORKSPACE_CONFIG`；保留已有合法值。
2. 第五轮：`support_EA` 按计划进入 EA 路径，配置中的 `head_newton` 不再覆盖该参考算法。
3. 第八轮：评估、支持集拟合和后续元训练查询损失的类别权重精度匹配计算张量，仍按 `0.5 / 类别样本数` 计算。
4. 第九轮：修正复制的损失精度错误，覆盖已排队及后续子任务。

## 执行方式

使用本目录 `RUN-ONE-LINE.sh` 中的一整行。程序只需 Python 标准库，不导入 Torch、不下载数据、不运行全量前置测试。

现有运行和排队作业保留；现有监督进程下次启动子任务时会读到修复，最长可能等待已有 300 秒重试间隔。所有后续子任务也走该入口。程序不会取消或重复提交作业，不会从头重跑已完成任务。旧的失败日志保留，修复后以新的会话/优化更新和完成回执推进为准。

## 断点与实验标识

原科学源码内容参与实验标识计算，直接修改会影响重新启动时的计划匹配。因此只更新不参与实验标识的 `backend_entry.py`，在指定 worker 导入时编译修正副本。原源码、计划、任务键、结果、断点均不改写；原分区、CPU、内存和上传进程均保留。

`result.json`、`runtime.json`、`error.json` 新回执会记录原始/执行源码 SHA、修复 SHA 和版本。完整归档可保留这些运行证据。GitHub 轻量结果和完整归档两条既有通道继续独立运行。

本地修复记录：`$HOME/paper3-runtime-fixes/r589-dtype-cublas-v1/APPLIED.json`。各轮 `runtime/runtime-corrections.json` 记录相同修复来源。重复执行修复命令会复用该版本；如果手动重新安装旧启动包，也应再执行本修复命令，以免旧包覆盖运行入口。

第六轮共用文件中的代码仅在第五、八、九轮入口生效；第六轮的分区、迁移和执行行为不改变。

## 验证范围

使用 Python 3.12.3、Torch 2.5.1+cu121、NumPy 2.2.6 验证；本地没有可用 GPU。

- 启动环境、实际导入修复及部署回归 37 项通过；额外实际修复钩子端到端 2 项通过。
- 第八轮完整软件测试 118 项通过。
- 第五轮软件测试 265 项通过；历史字节相同断言因本地源文件验证补丁单独排除，最终运行交付保持原源码字节。可选原始数据准备测试在本地提供 SciPy 后通过。
- 第五轮 EA 分派和第九轮精度专项回归分别 5 和 6 项通过。
- 新测试模拟 CUDA 严格索引赋值类型要求，复现旧错误；再运行实际 EEGNet、训练、选择、评估、外部缓存和断点续跑流程验证修复。

这些检查不声称学校 GPU 已恢复训练。安装成功事件为 `R589_REPAIR_APPLIED`；实际子任务采用修复的事件为任务 `.out` 中的 `RUNTIME_WORKER_CORRECTION`，训练进展仍需观察会话或更新计数。
