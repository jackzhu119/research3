# 第一轮跨节点断点恢复修复

用户回传的日志证实两个独立阻断：旧 P 工程记录使用驱动 550.54.14，当前 A100 节点使用 535.104.12；两边 Python 3.12.3、Torch 2.5.1+cu121、CUDA 12.1、cuDNN 90100、数值设置及源码一致。另一个任务在未正常关闭的计时间隔中换节点，触发永久 `boot_changed_or_unknown` 阻断。

此包仅修改第一轮外部运行包装器。原始模型、最新断点、RNG、采样器、任务身份、数据划分、种子和更新次数继续由原生实现校验和恢复。第六轮队列、第九轮以及其他项目不受影响。

## 修复内容

- 驱动迁移只接受已经在学校节点观察到的 535.104.12 与 550.54.14，在原框架版本一致时继续执行原来的全部比较。完整旧/新环境写入迁移记录；不替换真实设备信息，不声称跨驱动逐位相同。
- 跨节点计时恢复必须先通过原生最新断点完整性、身份和 RNG 校验。仅修复已证实的跨 boot 未关闭计时间隔，保留旧阻断、旧时钟观测和全部累计计费下限，再建立新的真实计时间隔。其他时钟异常不被静默忽略。
- 有不确定旧计时间隔的任务，其后续结果携带运行计时说明；旧间隔不被伪造成精确耗时。
- 安装入口覆盖现有主 action 包装器及后续 owned-stage 子进程；保留已安装的摘要缓存和之前的恢复逻辑。

## 执行与激活

`FIX-PAPER3-R1-RESUME.py` 是自包含的标准库安装程序。运行时不下载依赖、不导入 Torch、不扫描原始数据，也不提交或取消 Slurm 作业。

加 `--refresh-pretraining` 时，程序尝试进入三个现有 allocation，核对作业、槽位、claim、父子 PID、进程启动时间及命令行，仅向尚未开始本次数值训练的旧子进程发送 SIGINT，让原 supervisor 加载新入口重试。已有本次训练进度的子进程保留。若 allocation 内的小步骤不可用，则等待下一个原生子进程自动采用新入口。

安装成功不等于三个作业已经恢复数值训练。应核对 `R1_OBSERVED_CUDA_DRIVER_TRANSFER_ALLOWED`、`R1_CROSS_NODE_CLOCK_CHECKPOINT_RESUME_AUTHORIZED` 和各槽位新的 `outer_updates_completed`，以实际增加的更新次数确认恢复。

安装回执：`~/paper3-runtime-fixes/r1-resume-v3/APPLIED.json`。
备份与内容寻址的辅助代码保存在同一目录；旧进程引用的辅助文件不会被覆盖。

## 验证边界

专项测试使用本地 CPU 和软件测试数据，覆盖原生检查点的完整校验、RNG/采样器续跑、已观察的时钟记录、驱动迁移、错误拒绝及入口安装流程。没有将本地 CPU 测试描述为学校 A100 实测；学校实际恢复须以安装后的回传结果确认。

NVIDIA 驱动要求的来源与获取时间见 `CUDA_DRIVER_COMPATIBILITY_SOURCE.json`；学校故障摘要见 `OBSERVED_FAILURES.json`。
