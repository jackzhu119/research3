# 后续作业的运行与恢复审查

发现一项可复现的恢复兼容问题：运行入口修复后，重新执行旧的固定版本在线安装器，会因为该入口的 SHA 已改变而在安装验证阶段拒绝继续。它不会覆盖修复文件，也不影响已经运行或排队的子任务，但会阻碍下次手动恢复。

`resume_existing.py` 解决该恢复入口问题：读取本轮现有 `plan.json` 与 `runtime/three_jobs/launch.json`，保留原分区、CPU、内存、任务键、修复入口和断点；后台进程直接调用原来已安装的 `controller_loop`，不经过安装器或重新构建配置。

默认只显示现有配置。`--execute` 表示恢复第五、六、八或九轮原有控制器及监控；第九轮还会恢复原来的论文证据和完整归档通道。如果组件锁仍被现有进程持有，立即复用，不重复启动。该脚本不直接执行任何 sbatch 或 scancel，后续提交由本轮原来的持久调度器处理。

示例（脚本必须先放在学校服务器可持续读取的路径）：

```bash
/public/home/zhuziyuan/.venvs/paper3-hpc-cu121-offline/bin/python -I -S -B -u /path/to/resume_existing.py --round 8 --execute
```

恢复只适用于已经准备好的原始计划。第一轮和第四轮使用不同的原生运行接口，此辅助程序不会启动或迁移它们。第六轮恢复现有配置，保留 hpc_gpu1，不执行先前已取消的迁移方案。

本地运行检查：原生运行/上传测试168项通过，恢复兼容测试19项通过；包含第五、六、八、九轮真实原生控制器导入、保存配置的完整传递、存活组件锁复用，以及断点和计划字节保持。没有启动、停止或重新提交学校作业。
