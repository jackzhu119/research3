# Paper3 第八轮：有限前缀协方差输运与类别方向校正

本轮是根据前七轮设计及第二、三、七轮已回传结果制定的新实验。代码和安装包已在开发环境测试；**尚无第八轮学校 GPU 实验结果**。源 EEGNet 及其 BN/输入窗口保持冻结，只用目标会话前20个原始采集位置内的有效试次适配。内部 Stieger 和 Pan 已多轮查看，均标为探索性重复验证。

## 资源与启动

三个独立 Slurm 作业，每作业一个节点、一张 GPU、16 CPU 核、64G 主机内存，分区 `hpc_gpu`（A100 PCIe 40GB）。总计3GPU、48核、192G。节点可不同，不要求三卡同时空闲。程序使用现有学校 Python3.12.3 / Torch2.5.1+cu121 / NumPy2.2.6 环境。

在线启动指令见 `online/RUN-ROUND8.sh`。启动成功的后台 PID 只证明控制器启动；`SUBMITTED` 作业号证明 Slurm 接受提交；节点日志 `TRAIN_PROCESS_STARTED` 证明开始执行。实际训练看 `outer_update`，评价看 `session` 计数。

输出独立存放于 `/public/home/zhuziyuan/projects/paper3/runs/followup_20261025_r8`。已有第1—7轮作业和结果不参与迁移操作。

## 运行行为

- GPU节点不联网下载数据、不安装依赖、不运行全量pytest/pilot、不重新哈希全库。
- Pan、Weibo裁剪缓存随固定安装包交付；Stieger复用本地原缓存。只读必要的计划、源模型、索引和实际使用的会话。
- 学习任务每10次外层更新保存两代断点，含优化器和随机数状态；每个评价会话立即保存预测及指标。正常信号退出先保存；机器突然丢失至多回到最近完整断点，可能重算未提交部分。
- 每个任务独立锁定、独立保存。单个任务异常保留错误并退避重试，其余可执行任务继续；输入确实缺失时如实报告，不能把缺失任务伪装完成。
- 无累计12小时限制。单次Slurm申请5天3小时，接近时限发送保存信号，控制器续交同轮未完成工作；学校QoS/资源不足会排队。
- Github同步与训练分进程。网络失败本地结果照常保存，随后重试。同步的是进度、报告和轻量回执；完整逐试次预测与模型断点留在学校服务器。
- 重复执行同一启动命令采用已有本轮任务，读取原断点和完成回执。
